A lot of the businesses I speak to in Romford and East London already have a website, and a big share of those sites run on WordPress. Often it was set up years ago by a friend, a nephew or a cheap agency, and now it is slow, hard to change and nobody quite remembers the password. So the question comes up: should you fix the WordPress site, or start again with something custom-coded?

I have built on both, including my own old site, so this is an honest comparison rather than a sales pitch for one side.

## Why this question comes up

WordPress powers a huge part of the web, and for good reason. But a typical small business WordPress site is rarely "just WordPress". It is usually WordPress, plus a premium theme, plus a page builder such as Elementor, plus a stack of plugins for SEO, forms, cookie banners, caching, security, backups, reviews, WhatsApp buttons and so on. Each one solves a problem, but together they create new ones.

## Where WordPress is great

WordPress is a strong choice when:

- **You publish a lot of content yourself.** If you post articles every week, its editor and blogging tools are mature and familiar.
- **You need a big ecosystem.** There is a plugin for almost everything, and lots of people know how to work with it.
- **Several people edit the site.** User roles, drafts and scheduling are built in.
- **You want full control over editing** without going through a developer for every change.

For a busy blog, a news site or a business with an in-house marketing team, WordPress can make a lot of sense.

## Where it hurts small businesses

For a typical local business with a handful of pages that rarely change, the downsides tend to outweigh the benefits:

- **Constant updates.** WordPress core, the theme and every plugin need regular updates. Skip them and you risk security holes. Apply them and something occasionally breaks.
- **Security.** Because WordPress is so popular, it is a constant target for automated attacks. Outdated plugins are the most common way in.
- **Page-builder bloat.** Visual builders make editing easy, but they often load large amounts of code on every page. On a phone with a patchy signal, that means slow load times and visitors giving up.
- **Hosting costs.** WordPress needs a server running PHP and a database, so you pay for hosting that can handle it, and often for caching and security add-ons on top.
- **Fragility.** The more plugins you have, the more likely two of them will clash after an update.

None of these are deal-breakers on their own, but together they mean a "cheap" WordPress site can quietly cost time, money and enquiries.

## What "custom-coded" means

When I say custom-coded, I mean a site built specifically for your business using modern web tools, then published as fast, static pages. There is no database to hack, no plugins to update and nothing running on a server waiting to be exploited.

The benefits for a small business are straightforward:

- **Speed.** Pages are pre-built, so they load almost instantly.
- **Security.** With no admin login or plugins exposed to the internet, there is very little to attack.
- **Low running costs.** Static sites can be hosted very cheaply, sometimes for free.
- **No surprise breakages.** Nothing changes unless someone deliberately changes it.

The trade-off is editing. You do not get a WordPress-style dashboard, so content changes usually go through your developer. For most local businesses that is fine, because the content changes a few times a year, and on my Premium package small changes are included in the monthly support.

## Speed, Google and Core Web Vitals

Google measures how quickly your pages load and how stable they feel while loading, using a set of measurements called Core Web Vitals. Faster sites tend to do better in search results, and they definitely do better with real people: if a page takes too long on a phone, many visitors simply go back and tap the next result, which is often your competitor.

A lean custom site makes it much easier to score well on these measurements without endless tuning, caching plugins and image-compression add-ons.

## Which should you choose?

Here is a simple way to decide:

| Your situation | My recommendation |
| --- | --- |
| A few pages that rarely change, and you want it fast and low-maintenance | Custom-coded |
| You post articles or news every week yourself | WordPress (kept lean, with few plugins) |
| You need bookings, lead routing or a custom system | Custom-coded, with the system built in |
| Your current WordPress site is slow, broken or insecure | Usually a rebuild, unless it is a quick fix |
| A team of people needs to edit content daily | WordPress or a headless CMS |

## Moving from WordPress without losing rankings

If you decide to move, the biggest worry is usually losing the Google rankings you already have. That is avoidable if the move is planned properly:

1. **List your existing pages** and note which ones get traffic.
2. **Keep the same web addresses** where you can, or set up redirects from old addresses to new ones so Google and old links still land in the right place.
3. **Keep the content that works.** If a page ranks well, improve it rather than throwing it away.
4. **Submit the new sitemap** in Google Search Console once the new site is live, and keep an eye on any "page not found" errors for a few weeks.
